    #### Description:

    ## Summary
    This project explores the principles of random network graph theory, utilizing Dijkstra's algorithm to calculate the shortest path between a start and end point. Random networks have diverse applications in fields such as physics, particularly in percolation theory, as well as in educational tools for teaching graph theory and network modeling. Additionally, non-uniform cost minimization techniques, akin to Dijkstra's algorithm, are used in practical systems like GPS navigation to determine the most efficient route.

    ## Functionality

    ### User Inputs
    The program takes user inputs for customization, using a helper function to validate the inputs through a lambda function that enforces specific criteria. These inputs include the number of nodes, the graph's complexity, and the scale of the graph. The number of nodes is straightforward, while the graph complexity lets users adjust the degree of interconnectedness between nodes. The graph scale is a multiplier applied to the coordinates of the nodes, determining the spread or magnitude of distances between them.

    ### Vertex Generation
    Cartesian coordinates are generated for the specified number of nodes provided by the user. These coordinates are initially created as tuples within the range of 0 to 10 for both the X and Y directions. Random values are selected using the random module, and they are then scaled by the user-defined factor to determine their final (X, Y) positions.

    ### Edge Generation
    Erdős–Rényi logic is applied to determine where edges form between pairs of nodes. The probability of an edge forming is based on the number of nodes and the user-defined complexity factor. Using the random module, the function generates a random number between 0 and 1; if this number is less than the calculated probability, an edge is created between two nodes. The function ensures that no duplicate edges are formed and that nodes are not connected to themselves. The edges are stored in a list, with each edge represented as a tuple (Node1, Node2).

    ### Node Class
    To practice object-oriented programming, I implemented a Node class to encapsulate all relevant information for each node. After determining the vertices and edges, a new Node object is created for each node, storing its (X, Y) coordinates and a list of its neighbors. Class methods are used to calculate the distance between a node and its neighbors, with the results stored in a dictionary where the keys are neighboring nodes and the values are the corresponding distances.

    ### Breadth-First Search
    A deque was used to implement a breadth-first search (BFS) to identify all nodes connected to the user-specified start node. This step ensures that the end node is reachable from the start node before attempting to find the shortest path between them. The function is encapsulated within a while loop that runs until the user inputs two valid, connected nodes from the network graph.

    ### Shortest-Path (Dijkstra's Algorithm)
    Shortest-path uses a priority queue (min-heap) to determine the lowest cost required to reach any node connected to the start (parent) node. The priority queue is a data structure that orders elements based on priority—in this case, the shortest distance to each respective neighbor. The implementation creates a dictionary where connected nodes are the keys, and their neighbors are the values. A separate function reconstructs the path as a list from the start to the end node, using the parent dictionary generated by Dijkstra's algorithm. Finally, I created a custom function to calculate the total distance required to traverse the path from start to end, using the instance variables of the nodes.

    ### Graph Generation
    The external library NetworkX, along with matplotlib.pyplot, was used for generating and visualizing the network graph. Nodes and edges were manually added to align with my preference for using a Cartesian coordinate system to calculate literal distances between coordinates on the (X, Y) plane. Several customizations were applied to enhance graph readability, including node transparency, coloring, and font styling. The nodes along the determined path are colored red, while the others are colored blue, using list comprehension. Due to difficulties with graph pop-ups in the CS50 VSCode environment, the plot is saved as a PNG. In the future, I would consider using Jupyter notebooks (e.g., ipynb) for better visualization support.
